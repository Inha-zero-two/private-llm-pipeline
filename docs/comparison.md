# 비교 기능

**대상:** [server/comparison](../server/comparison). 같은 질문에 대한 파이프라인 · 로컬 단독 · 프론티어 단독의 답변을 한 화면에 나란히 보여 주고 저장한다. 파이프라인 모듈이 아니다.

목적은 우리 파이프라인이 로컬 단독보다 낫고 프론티어 단독과 비슷한 답변 품질을 낸다는 것을 보여 주는 것이다. 점수 측정(사람 평가, AI 심판, 고정 질문 세트)은 하지 않는다.

## 개인정보

**켜져 있으면 질문 원문이 동의 창이 뜨기 전에, 별도 확인 없이 두 모델로 전송된다.** 사용자가 공개를 거절한 개인정보도 포함된다. 중지하거나 채팅을 지워도 이미 보낸 것은 되돌릴 수 없다.

- 프론티어 단독: `FRONTIER_BASE_URL`의 게이트웨이로 보낸다.
- 로컬 단독: 항상 원격 모델 서버로 보낸다. PC의 GPU로 파이프라인을 돌려도 같으며, 이때는 두 모델 파일이 다를 수 있다.
- 질문 원문과 답변은 DB의 `comparisons`에도 저장된다.

입력창 아래·첫 화면·동의 창의 문구는 파이프라인 기준의 설명이며 비교 기능에는 적용되지 않는다. 보내지 않으려면 `COMPARISON_ENABLED`를 끈다.

## 설정

| 이름 | 기본값 | 내용 |
| --- | --- | --- |
| `COMPARISON_ENABLED` | 켬 | `0`·`false`·`off`·`no`(대소문자 무시)면 끔. 서버 시작 시 한 번 읽는다 |
| `FRONTIER_API_KEY` · `FRONTIER_BASE_URL` · `FRONTIER_MODEL` | 파이프라인과 같음 | 프론티어 단독도 같은 모델·주소·키를 쓴다 |

| 상황 | 비교 |
| --- | --- |
| 켜진 상태에서 만든 채팅 | 함 |
| 기능 추가 전이나 꺼진 동안 만든 채팅 | 하지 않음 |
| 비교하던 채팅에서 꺼진 동안 질문함 | 다시 켜도 하지 않음. 저장된 기록은 남아 볼 수 있다 |

## 구조

```text
app/api/app.py    ──▶ comparison        (호출부만 비교 기능을 앎)
comparison        ──✕──▶ app
app의 나머지 모듈  ──✕──▶ comparison
```

| 파일 | 내용 |
| --- | --- |
| `api.py` | 결과 조회 · 실시간 전송 · 재시도. 응답 형식은 [API 명세](screen-api-spec.md#비교-기능-api) |
| `manager.py` | `ComparisonManager`: 두 비교의 실행과 중지 |
| `local.py` / `local_context.py` | 로컬 단독 호출 / 앞 대화 만들기와 길이 처리 |
| `frontier.py` | 프론티어 단독 호출과 앞 대화 만들기 |
| `store.py` | 비교 기록 읽기·쓰기. 자기 테이블만 쓴다. [DB 스키마](db-schema.md) |
| `models.py` | 비교 전용 자료형 · 오류 코드 · 취소 신호 |

`create_app(comparison_factory=None)`이면 비교 기능이 없다. 맨 아래의 `app`만 실제 비교 기능을 만들므로, 테스트는 실제 모델을 부르지 않는다. 비교 기능을 준비하지 못하면 로그를 남기고 비교 없이 서버를 시작한다.

## 모델에 보내는 것

| | 로컬 단독 | 프론티어 단독 |
| --- | --- | --- |
| 메시지 | `user` 하나. 앞 대화를 글로 이어 붙임 | 앞 대화를 `user`/`assistant`로 나눠 매번 다시 보냄 |
| 출력 상한 | 5,000토큰 | 4,096토큰 |
| 입력 한도 | 26,744토큰 (32,768 − 5,000 − 1,024) | 100,000자 (임시값) |
| 길 때 | 오래된 질문·답변 쌍부터 제외 | 오래된 질문·답변 쌍부터 제외 |
| 자동 재시도 | 없음 | 글이 나오기 전의 네트워크 오류·429·5xx만 최대 3번 시도 |

- `system` 메시지를 넣지 않는다. 모델만 썼을 때와 비교하는 것이 목적이다.
- 프론티어 단독의 Chat Completions 출력 상한은 `max_completion_tokens=4096`으로 보낸다. 현재 모델이 지원하지 않는 구식 `max_tokens`는 보내지 않는다.
- 앞 대화는 같은 모델이 `ok`로 끝낸 질문·답변만 쓴다. 세 모델은 서로의 답변을 보지 않는다.
- 질문만으로 한도를 넘으면 `INPUT_TOO_LONG`이다.
- 요청마다 연결을 새로 만든다. 중지하거나 120초를 넘으면 취소 표시를 남기고 연결을 닫는다. 닫은 뒤 작업 스레드에서 나는 예외는 실패로 기록하지 않는다.

## 실행

```text
질문 전송 (API-05)
   ├─ 자리 예약 ─▶ 파이프라인 시작 ─▶ 실행 번호
   └─ 실행 번호를 받은 직후 비교 시작
        기록 2줄 추가(running) ─▶ 앞 대화 읽기 ─▶ 두 모델 호출 ─▶ 저장 ─▶ 자리 놓기
```

- 세 출력은 서로를 기다리지 않는다. 한쪽이 실패해도 나머지는 계속한다.
- 세 출력이 모두 끝나야 다음 질문을 받는다. 그 전에는 409 `COMPARISON_RUNNING`(파이프라인이 진행 중이면 `RUN_IN_PROGRESS`)이다.
- 확인과 예약, `pipeline.start()` 사이에는 `await`를 두지 않는다. 다른 질문이나 재시도가 끼어드는 것을 막기 위해서다.
- 기록을 만들지 못하면 파이프라인만 진행한다. 기록을 만든 뒤 시작하지 못하면 `failed` / `INTERNAL`로 끝낸다.

### 중지

`POST /api/runs/{runId}/stop` 하나가 파이프라인과 비교를 함께 중지한다. 이미 끝난 답은 바꾸지 않는다.

### 다시 시도

모델 하나를 같은 줄에서 다시 실행하고 `attempts`를 올린다. 아래를 모두 만족해야 한다.

1. 켜져 있고 비교 대상 채팅이다.
2. 그 채팅의 마지막 질문이다. 비교 기록이 아니라 파이프라인의 마지막 실행을 기준으로 한다.
3. 상태가 `failed`, `truncated`, `stopped` 중 하나다.
4. 진행 중인 비교나 파이프라인 실행이 없다.

## 상태와 오류 코드

| 상태 | 뜻 | 다음 질문의 앞 대화 |
| --- | --- | --- |
| `running` | 생성 중 | 넣지 않음 |
| `ok` | 정상 완료 (`finish_reason`이 `stop`) | 넣음 |
| `truncated` | 출력 상한에서 잘림 (`length`) | 넣지 않음 |
| `failed` | 실패 | 넣지 않음 |
| `stopped` | 사용자가 중지 | 넣지 않음 |

| 오류 코드 | 뜻 |
| --- | --- |
| `KEY_MISSING` | 키 없음 (로컬은 키 파일, 프론티어는 API 키) |
| `INPUT_TOO_LONG` | 질문이 입력 한도를 넘음 |
| `TIMEOUT` | 120초 초과 |
| `UNAVAILABLE` | 연결 실패, 5xx |
| `AUTH_ERROR` | 401, 403 |
| `RATE_LIMITED` | 429 |
| `QUOTA_EXCEEDED` | 한도 소진. 이 게이트웨이의 422이거나 한도 소진 오류 코드 |
| `REJECTED` | 400 등 그 밖의 요청 거부 |
| `EMPTY_RESPONSE` | 글이 비어 있음 |
| `STREAM_BROKEN` | 글을 받는 도중이나 `finish_reason` 없이 끊김 |
| `INTERRUPTED` | 서버가 다시 시작됨 |
| `INTERNAL` | 그 밖의 오류 |

화면에는 코드별 고정 문구를 보여 준다. 로그에는 예외의 종류와 HTTP 상태만 남긴다. 예외 원문과 응답 본문은 질문을 되풀이할 수 있어 남기지 않는다.

## 화면

오른쪽 위는 로컬 단독, 아래는 프론티어 단독이다. 질문·상태·답변·걸린 시간은 항상, 토큰·비용·모델·시도 횟수·앞 대화 개수는 "자세히"를 펼치면 보인다. 파이프라인의 걸린 시간은 동의를 기다리고 해석한 시간을 뺀 값이다.

## 확인이 필요한 것

- 로컬 모델 서버가 `system` 없는 요청을 받는지
- 로컬 모델 서버의 현재 동시 처리 수
- `bedrock-gpt-6-luna`의 입력 한도 (`INPUT_LIMIT_CHARS`)
- 연결을 끊으면 실제 로컬 모델 서버가 생성을 멈추는지
