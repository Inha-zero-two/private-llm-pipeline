# 개인정보 검출 평가

정답이 달린 문장 데이터셋을 PDDetector에 하나씩 넣어 **검출이 맞는지**와 **많이 돌려도 안정적인지**를
잽니다. 파이프라인 전체는 돌리지 않고, 실제 검출 경로(LocalLLMRunner의 DETECT 요청 → PDDetector
검사)만 씁니다.

데이터는 한 줄에 문장 하나인 JSONL입니다. `id`는 생략하면 줄 번호, `category`(0 식별 · 1 민감 ·
2 속성)는 생략하면 분류를 채점하지 않습니다. 예시는 `server/qa/datasets/pd_sample.jsonl`.

```json
{"id": "s1", "text": "제 번호는 010-1234-5678이에요", "pd": [{"text": "010-1234-5678", "category": 0}]}
{"id": "s2", "text": "부산까지 KTX로 얼마나 걸려요?", "pd": []}
```

```bash
cd server
CUDA_VISIBLE_DEVICES=-1 ../src/localLLM_API_proxy/.venv/Scripts/python -m qa.pd_eval 데이터.jsonl
# --limit 50 으로 앞부분만, --out 폴더 로 결과 위치 지정
```

결과는 `server/qa/results/pd-<시각>/`에 남습니다. (git 제외)

- `results.jsonl`: 문장별 결과. 한 줄씩 바로 기록하므로 중간에 멈춰도(Ctrl+C) 남고, 그때까지로 요약합니다
- `summary.md`, `summary.json`: 아래 지표와 놓친 항목·과검출·분류 오류·실패 문장 예시

| 구분 | 지표 |
| --- | --- |
| 정확도 | 정밀도(검출 중 정답), 재현율(정답 중 검출), F1, 분류 정확도, 분류별 재현율, 문장 완전 일치율 |
| 안정성 | 성공/실패 수와 실패 사유(`parse_failed` 형식 오류, `unavailable` 연결 실패, 예외 등), 지연 평균·p50·p95·최대, 처음 10% → 마지막 10% 평균 지연(오래 돌릴수록 느려지는지), 토큰 수 |

정답과 검출은 공백·하이픈·점을 지우고 비교하며, 한쪽이 다른 쪽을 포함하면 같은 항목으로 봅니다.
(`010-1234-5678` = `01012345678`, `27살` = `저는 27살`) 정답 하나에는 검출 하나만 짝짓습니다.
원격 서버 기준으로 문장당 1초 안팎이라 1000문장은 15분 정도 걸립니다.

`server/tests/test_pd_eval.py`가 검출 대역으로 채점·요약 로직을 검사하며 CI에서 돕니다. 실제 모델 평가는 키가 있는 PC에서 직접 실행합니다.
