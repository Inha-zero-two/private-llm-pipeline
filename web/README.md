# web — 채팅 화면

React + Vite (TypeScript). 상세 설계서 9장의 화면 세 개(메인 채팅, 추가 개인정보 공개 요청, 공개 허용 설정)를 만든다.

## 실행

화면은 앱 서버(`server/app/api`, 명세서 `docs/screen-api-spec.md`)에 연결된다. 서버를 먼저 켠다.

```bash
# 1) 앱 서버 (저장소 루트에서). 모든 단계가 실제 모듈로 돈다
cd server
#   로컬 LLM: 원격 모델 서버 키를 src/localLLM_API_proxy/keys/llama_api_key.key에 둔다
#   프론티어: server/.env.example을 server/.env로 복사해 FRONTIER_API_KEY를 채운다
#   채팅 기록: server/data/chat.sqlite3 (CHAT_DB_PATH로 변경)
CUDA_VISIBLE_DEVICES=-1 PYTHONPATH=.. ../src/localLLM_API_proxy/.venv/Scripts/python -m uvicorn app.api.app:app --port 8000

# 2) 화면 (다른 터미널)
cd web
npm install
npm run dev        # http://localhost:5173, /api 요청은 127.0.0.1:8000으로 프록시
```

| 명령               | 내용                                      |
| ------------------ | ----------------------------------------- |
| `npm run dev`      | 개발 서버 (앱 서버 연결)                  |
| `npm run dev:demo` | 개발 서버 (서버 없이 브라우저 안 데모)    |
| `npm run build`    | 타입 검사 + 빌드                          |
| `npm run lint`     | oxlint                                    |
| `npm run format`   | Prettier로 정리 (`format:check`는 검사만) |

## 데모 동작

`npm run dev:demo`로 켜면 서버 없이 브라우저 안 데모(`src/demo`)가 설계서 흐름(①~⑧)대로 진행 단계와 답변을 채운다. 데이터는 메모리에만 있어 새로고침하면 사라진다. 서버에는 연결하지 않는다.

### 데모 시나리오

질문에 아래 낱말을 넣으면 해당 상황을 볼 수 있다.

| 질문에 넣을 것                                                                               | 상황                                     |
| -------------------------------------------------------------------------------------------- | ---------------------------------------- |
| 나이(`27살`), 전화번호, 이름(`제 이름은 홍길동`), 회사 · 학교 이름(`삼성전자`, `인하대학교`) | 추가 공개 동의 요청                      |
| `동의`                                                                                       | 위 항목이 없어도 예시 항목으로 동의 요청 |
| `오류`                                                                                       | 실행 오류                                |
| `오프라인`                                                                                   | 외부 모델 연결 불가                      |
| `상한`                                                                                       | 질문 상한 도달                           |

- **공개 동의 요청**은 입력창 위에 상자로 뜬다. 자연어로 답하면(예: "나이는 공개하고 직장은 공개하지 마") 항목별로 공개 여부를 정한다. 언급하지 않은 항목은 공개하지 않는다. 하나도 공개하지 않으면 거절로 본다.
- **공개 허용 설정**은 앱 전체에 하나다. 사이드바 왼쪽 아래 버튼으로 연다. 허용한 종류(예: "나이는 공개해도 돼")는 동의를 묻지 않는다.

## 구조

```
src/
  types.ts          화면에서 쓰는 자료형
  backend/          화면이 쓰는 백엔드 약속(types) · 앱 서버 연결(remote) · 데모 연결(demo)
  demo/             브라우저 안 데모 실행 · 시나리오 · 설정문 해석
  components/       사이드바, 대화, 입력창, 동의 창, 설정 창 등
  comparison/       비교 패널 · 비교 API 호출 · 실시간 상태 (docs/comparison.md)
  App.tsx           채팅 목록 · 실행 상태를 들고 화면을 조립한다
```

## 비교 패널

오른쪽 위는 로컬 단독, 아래는 프론티어 단독의 답변이다. 기본은 최근 질문이고, 대화에서 지난 질문을 누르면 그 질문의 답으로 바뀐다. 서버에서 꺼져 있거나(`COMPARISON_ENABLED`) 데모이면 패널을 숨긴다. 세 출력이 모두 끝날 때까지 다음 질문을 보낼 수 없고, 중지 버튼 하나로 모두 멈춘다.

# 실행 종료 사유 표시

실행 로그는 서버의 `done.endReason`과 API-11의 `endReason`을 `Turn`에 보존해 같은
매핑으로 표시합니다. 답변 아래의 상세 안내는 별도로 유지합니다.

| endReason    | 상태           | 종료 사유                |
| ------------ | -------------- | ------------------------ |
| info_enough  | 완료           | 정보 충분                |
| call_limit   | 제한 종료      | 외부 질의 횟수 한도 도달 |
| regen_limit  | 제한 종료      | 요청문 재생성 한도 도달  |
| budget_limit | 제한 종료      | 비용 한도 초과           |
| offline      | 외부 연결 불가 | 외부 모델 연결 불가      |
| stopped      | 중지됨         | 사용자 중지              |

공개 거부 후 계속 처리하는 서버 변경은 PR #68에서 제공합니다. 과거 `consent_denied`
기록은 과거 종료임을 명시하며, 새 종료 사유로 사용하지 않습니다. 오류는 “오류 종료”,
누락된 서버 값은 “종료 사유 미제공”으로 표시합니다. 데모 대체 문구는 데모 모드에서만
사용합니다. 오류는 서버의 code·stage·고정 안내문을 보존하며, 실시간과 기록 조회에서
동일한 오류 코드·발생 단계를 표시합니다. 코드나 단계가 없는 과거 기록은 미제공으로 표시합니다.

`npm test`는 서버 없이 Node의 내장 테스트 실행기로 실제 어댑터의 SSE 완료 처리와 API
기록 복원, 종료 사유 매핑을 검사합니다. Node 22에서는 타입 제거 실험 기능 경고가 나올 수 있습니다.
